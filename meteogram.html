Modele na wspólnej osi czasu

Porównanie oryginalnych terminów. Brakujące wartości pozostają przerwami; serie o różnych jednostkach nie są łączone.

Połączenie i dane

Odczytano kontrakt z wcześniejszego meteogram.html: GET /meteorograms/available, POST /available_models/ z obiektem punktu oraz POST /meteorograms/{model} z {date, point}. Nie potwierdzono go na podstawie HAR ani działającej odpowiedzi serwera. Adres starego API może być nieaktualny.

Przeglądarka musi mieć zgodę serwera na CORS, również dla pochodzenia null przy otwieraniu pliku. Tego ograniczenia nie da się wyłączyć z HTML. Przy błędzie zaimportuj JSON; portal nie wysyła danych przez publiczne serwery proxy.

Import: oryginalna odpowiedź API {data:{parametr:{data:[],first_timestamp,interval,unit,point,fstart}}}, eksport wcześniejszego skryptu {model,forecast,parameters,static_parameters}, pakiet tego portalu oraz odpowiedzi JSON zapisane w HAR. Nazwa pojedynczego pliku powinna zawierać um4_60, um4_120 lub gfs. HAR jest przetwarzany lokalnie, wyłącznie odpowiedzi meteogramów.

UM4 60/120 to horyzonty prognozy; rzeczywiste daty startu i dostępność pobierane są z API. Prognoza dobowa przedstawia zakres temperatur w dostępnych terminach, a nie gwarantowane ekstremum dobowe. Jednostki pozostają zgodne z odpowiedzią źródłową.

Źródło danych: meteo.pl / ICM UW. Czas wykresów: Europe/Warsaw. Jednostki oryginalne z API; bez domyślnych przeliczeń. Dane demonstracyjne są historyczne. Kody opadów i wskaźniki nie mają tutaj przypisanej niezweryfikowanej interpretacji.
